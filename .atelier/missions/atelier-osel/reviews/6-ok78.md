## Finding 4: diru's isolation check and spike recipe still miss the OpenCode folders T3 reads
Recommendation: fix now
diru requires that OpenCode "runs from the instance's own home, with no
folder of the human's linked or copied in, so it holds no credential and
cannot reach a paid model" (`.atelier/items/atelier-diru/item.md` line 30),
and Out forbids signing in a provider that spends the human's allowance
(line 41). The isolation check still only lists `~/.t3` before and after
(line 29). Context (line 45) names the spike's isolation as `T3CODE_HOME`,
`T3CODE_PORT`, `T3CODE_DISABLE_AUTO_UPDATE` and `--user-data-dir`.

Those isolate T3 Code, not OpenCode. T3's OpenCode reader resolves data
dirs from `XDG_DATA_HOME` else `$HOME/.local/share/opencode`
(`~/projects/t3code/packages/provider-opencode/src/server/usage.ts`
lines 314–320). T3's own Linux smoke keeps `HOME` real and sets
`XDG_CONFIG_HOME` and `XDG_DATA_HOME` under the instance directory
(`~/projects/t3code/scripts/smoke-desktop-app.ts` lines 46–55). On this
host `~/.config/opencode/service.json` is mode 600 and
`~/.local/share/opencode` holds `opencode.db` and session logs.

The thread diru needs is "made inside T3 Code" (line 30), which the spike
did not try (line 45). An implementer who copies the context's env list
will leave `HOME` as the human's, skip `XDG_*`, and still pass the `~/.t3`
check while in-app OpenCode reads those live folders and can pick a paid
model. The command still only refuses a non-free model it is given
(line 30).

Name `XDG_CONFIG_HOME` and `XDG_DATA_HOME` (or `HOME` under the instance
directory) among the instance's own folders, as T3's smoke does. Extend
the isolation check to the real `~/.config/opencode` and
`~/.local/share/opencode`. Keep the refuse-non-free check.
