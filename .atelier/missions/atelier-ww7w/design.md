## Design

### 1. Fast record-only CI (`atelier-1n49`)
- Move `scripts/t3-extension-release.test.sh` out of the `changes` job and into the `extension` job (adding `scripts/t3-extension-release*` to `needs_extension` in `scripts/ci-jobs.sh`). Remove `pnpm/action-setup` and `actions/setup-node` from `changes`.
- In `scripts/ci-jobs.sh::needs_rust`, replace `.atelier/issues/* | .atelier/reviews/* | .atelier/evidence/* | .atelier/runtime/*` with `.atelier/items/* | .atelier/missions/* | .atelier/runtime/*`. Keep `.atelier/config.toml` triggering `rust`.
- Add `cargo clippy --all-targets --locked -- -D warnings` to CI's `test` job. (`clippy` is already clean on `master` under toolchain 1.95.0.)

### 2. Incremental plan reviews & round caps (`atelier-h6ij`)
- **Plan review delta (`plan.rs` + `review.rs::plan_review` + `output.rs::plan_brief`):** Compute the prior completed plan-review round (highest `round < current` where every review file has a verdict). When all reviews of that round share one commit `prev` that exists and is an ancestor of `HEAD`, compute changed plan paths with a dedicated helper (not `plan_changed_at`, which keeps `notes.md` and includes all mission item directories even from `base` merges):
  - Proposed mission (`!agreed`): `.atelier/missions/<id>/` (less `reviews/` and `notes.md`) plus `.atelier/items/<item>/` for items of `<id>` at `prev` or `head` (less any item `reviews/`).
  - Amendment of an agreed mission (`agreed`): `.atelier/missions/<id>/` (less `reviews/` and `notes.md`) plus `.atelier/items/<item>/` (less any item `reviews/`) for items of `<id>` at `prev` or `head` **that the amendment branch itself changed relative to `base`** (`git diff <base>...<head>`), intersected with paths differing between `prev` and `head`. That keeps the amendment's own item edits in the delta while excluding item Reports and reviews merged into `base` between rounds.
  - When the path list is non-empty, print `git diff <prev> <head> -- <plan-paths>` first and narrow the brief to carried findings and changes since the prior round (blocking on unchanged plan sections only if a serious defect was missed). When empty, print that the plan is unchanged since the prior round and tell the reviewer to judge carried findings (never `git diff` with an empty pathspec). Fall back to the full plan brief only when `prev` is missing, differs across the round's reviews, or is not an ancestor of `HEAD`.
- **Code review delta guard (`review.rs::brief`):** Guard `previous` in `later_round`: omit `git diff <prev> <commit>` if `prev` is missing or not an ancestor of `commit`; if `prev..commit` includes a merge from `base`, scope the delta diff to paths changed on the branch (`base...commit`) or fall back cleanly so unrelated `master` commits do not flood the diff.
- **2-split-round plan exit (`atelier-core::plan`, `commands.rs`, `output.rs`):** A completed plan round is *split* when it has at least one `approve` and at least one `changes` verdict. Count trailing consecutive split rounds **only among rounds added by the plan change under review** (present at `head`, absent from `base_tip`), so a mission whose initial plan merged after 2 splits (like `atelier-kw8u` or `atelier-to83`) starts any later amendment at 0 splits. When `>= 2` (on either a mission branch `<mission-id>` or an amending `backlog/*` branch):
  - `atelier submit` refuses to open another review round (offering `ATELIER_SKIP` so the human can authorize one more round after an amendment) and tells the planner to bring the open findings to the human to rule.
  - `atelier status` (adding plan review status output on mission branches and amending backlog branches) and `output::plan_unapproved` print the same human-ruling exit instead of telling the planner to submit another round.
  - `output::plan_submitted` notes the 2-split-round exit rather than unconditionally instructing another `submit`.
- **3-round code cap (`output.rs` / `say.rs`):** When an item is `changes_requested` and its latest completed round is `>= 3`, `status` (for implementer and mission lead) **replaces** `Then: atelier submit` with guidance to escalate to the mission lead (or starting thread) to settle (`ATELIER_SKIP="<ruling>" atelier merge`, adjust `Scope`/`Done when`, `drop`, or rule to fix — noting that once the lead rules to fix, `atelier submit` opens the next round).

### 3. Single-branch drop & branch cleanup (`atelier-gqtw`)
- **Single-branch drop:** Allow `atelier drop <id> --reason "<why>"` on a `backlog/*` branch even when `<id>` is started. Write `status: dropped` + `Dropped: <reason>` to `.atelier/items/<id>/item.md` (using `carry_drop`'s `Goal`/`Done when`/`Scope` copy when `<id>` only exists on its branch via `start --new`). Inspect paths added on `<id>`'s branch relative to `base` for any other `.atelier/items/<other>/item.md` not on `base`, and print them so `atelier-dh7a`/`atelier-u6oy` items are never silently lost. Keep branch-side `drop` on `<id>`'s branch working too, and update `skills/agent-factory/roles/lead.md` and `docs/design.md` to teach the single-branch drop.
- **PR close on merge:** When `atelier merge` merges a backlog branch that transitions a started item (whose branch exists) to `dropped` and a forge is configured, best-effort close any open PR for that item's branch (`Github::close_pull_request`), warning on failure without failing the merge.
- **Claim safety with branch deletion:** Because deleting a merged branch removes the remote ref that previously stopped a stale clone's `claim_push`, replace that protection directly:
  - When a remote is configured, `start` (both fresh start and take-over) fetches `<remote>/<base>` first and judges against it, refusing any `done` or `dropped` item. After the push, it re-checks `<remote>/<base>` to close the fetch-to-push race window:
    - On a losing **fresh `start` claim** (`begin`, before switching), delete only the local branch, do not switch, refuse, and warn about the pushed remote branch (`Located::record` rule 1 ensures `done`/`dropped` on `base` still wins; remote branches are deleted only by `atelier merge`).
    - On a losing **take-over**, delete **neither** the remote branch nor the local branch (preserving the earlier implementer's unmerged work and keeping a valid `HEAD`), refuse, and name the branch.
  - When a remote is configured, `submit` also fetches/checks `<remote>/<base>` and refuses if the item is already `dropped` or `done` there.
  - `atelier merge` deletes **neither** the remote branch nor the local branch unless this clone's `base_tip` contains `<head>` (so a failed `catch_up` leaves both refs intact).
- **Merged-branch cleanup on `atelier merge`:**
  - **Remote:** Once `base_tip` contains `<head>` and a forge is configured, best-effort delete the merged remote branch using `git push <remote> --force-with-lease=refs/heads/<branch>:<head> --delete <branch>` (never plain `--delete`, which could destroy a late push, and never `gh pr merge --delete-branch`, which tries to switch the linked worktree to `base`). Warn rather than fail if the remote refuses. Update `AGENTS.md:71` and `docs/design.md` per Sumeet's 2026-11-22 approval.
  - **Local:** Once `base_tip` contains `<head>`, if the current checkout is still on `<branch>` at `<head>` with no uncommitted changes (`uncommitted` empty), detach `HEAD` at `<head>` (`git switch --detach <head>`), delete `<branch>` at that exact commit with `git::delete_branch(&root, &branch, &head)`, and print a one-line pointer to `atelier start --backlog <slug>` / `atelier start <id>` for further changes. If uncommitted dirt was skipped via `ATELIER_SKIP`, leave `<branch>` attached and print a one-line hint.
- **Detached `HEAD` guard:** Planning commands (`new`, `set`, `ready`, `drop`, `close`, `lead`, `settle`) refuse to run on a detached `HEAD` (while `review` and `verdict` still allow detached reviewer worktrees by keeping `review.rs::on_base` focused on the base checkout). If `HEAD` is detached and `git for-each-ref --contains HEAD refs/heads refs/remotes refs/tags` is empty (explicitly ignoring non-branch/tag refs such as T3's `refs/t3/*` checkpoints), `status` reports the unattached commit(s) and `start` refuses to switch away without `ATELIER_SKIP`.
- **Desk PR fallback & eval fixtures:** In `crates/atelier-desk/src/server.rs`, when `page.row.branch` is `None` on a `done`/`dropped` item (or `page.mission.branch` is `None` on an agreed/done/stopped mission), fall back to `desk.pull_request(&repo, &dir, &branch_of(id))` so PR links stay populated in the Desk and `t3-extension/`. Update `evals/agent-factory/` fixtures (`loop/test_grade.py`, `settle-within-authority/setup.sh`) that assumed the merged local branch stayed behind.
- **Read-only stale hygiene notice:** In `atelier status` away from an item branch, count all merged local branches (not only convention-named ones) and detached worktrees; when either meets its threshold (e.g., `>= 20` merged local branches or `>= 10` detached worktrees), print a read-only summary with `git branch --merged <base>` and `git worktree list`. Never suggest a destructive command that could remove live reviewer worktrees.

### 4. Five CLI paper cuts (`atelier-zc9b`)
- `u49o`: `submit` passes the item checkout's root path (`repo.root`) into `start_reviewer` so the task reads `In <path>, run atelier review <id> and follow what it prints.` (shell-safe quoting if needed, no backticks).
- `o2vv`: Remove the automatic `Then: atelier start <first-ready>` line in `output::overview` when the caller holds nothing; list startable items and let the thread's task choose. Add a note in `SKILL.md` and `AGENTS.md` about running `atelier status` in the task's checkout when started from another repo.
- `yhaf`: In `output::overview`, when on `base` and the caller holds an item, look up `git::checkout_of` for that item's branch and print the existing checkout path or `git worktree add`, never `Then: atelier start <id> (switches to its branch)`.
- `jfos`: Update `output::push_refused` and `output::push_moves_base` so the printed steps, run verbatim on a checked-out base, move the commit onto a new item branch (`start --new`, which branches from local `HEAD` when strictly ahead of `<old>`, with cherry-pick only when bases diverged) and restore `base` to `<old>` via `git reset --keep <old>` (which preserves uncommitted work, or refuses cleanly without modifying files when uncommitted changes overlap the bad commit, with a note on finishing the reset after stashing/saving).
- `o91z`: In `crates/atelier-core/src/records/body.rs` (and its callers in `records/store.rs`, `actions.rs`, `review.rs`, `disputed.rs`, `crates/atelier-desk/src/read.rs`), parse `### Responses` leniently into valid responses plus malformed-line `Problem`s so a bad line never wedges `ItemDir` loading with exit 2. `status`, `show`, and `review` stay usable while reporting the bad line; `atelier check`, `atelier submit`, `atelier verdict`, and `atelier merge` refuse it so a malformed `not built:` line is never silently ignored. Update `docs/design.md` and `docs/product.md`.

### 5. Garden decoupling (`atelier-7637`)
- Update `skills/agent-factory/procedures/garden.md` (opening + Steps 1, 4, 5, 6, 7), `skills/agent-factory/SKILL.md` ("Who Works With the Human"), `docs/product.md`, and `docs/design.md`:
  - Once independent review approves the garden run branch, the gardener runs `atelier merge` immediately (landing upkeep fixes and deferred-finding settlements).
  - Immediately after merge, using one **stable** backlog slug `garden-proposals` (`backlog/garden-proposals`, never a dated slug and never a second slug): if `backlog/garden-proposals` already exists locally or on the remote (**whether merged or unmerged**, without assuming `atelier-gqtw` deleted it), work in the checkout that holds it if one does, otherwise switch to it and bring `base` in (fast-forward if merged, merge `base` if unmerged); call `atelier start --backlog garden-proposals` only when neither local nor remote has it. File or update the single open `"Garden proposals"` `needs-human,garden` item (identified by labels + fixed title so `atelier-j86z` is ignored) linking to the merged run's Report, and file any bugs found during the run as `bug,needs-human` items (with `--caused-by`) on the same branch, then submit and merge it.
  - Updating `"Garden proposals"` keeps **every** unanswered proposal (tagging each with its run/date) alongside up to 3 new proposals from the current run; only the human's answer removes a proposal.
  - Step 4 reads open/recently closed `"Garden proposals"` items, open/recently closed `bug` items, **and** the last merged garden run's `## Report` (`Proposals` and `Bugs to file` sections) so any proposals or bugs from a run that stopped before merging `backlog/garden-proposals` are recovered.
  - Once the human answers `"Garden proposals"`, a planner applies the agreed proposals (`atelier new` / `atelier ready` on a backlog branch), closing `"Garden proposals"` (`atelier close <id> "<decisions>"`) only once **every** proposal in it is answered (otherwise removing only the answered proposals and leaving unanswered ones open).

### 6. Desk mission history (M5) backed by `atelier_core::log::history` (`atelier-js4a`)
- Add mission-plan lifecycle actions to `crates/atelier-core/src/log.rs`:
  - `Happened::Plan` (printed as `plan`) when a mission record first appears as a new `open` plan (without a pre-existing `lead`/`Result` and whose `created_at` does not predate the commit by more than 24h, avoiding falsely dating bulk-converted pre-cutover missions such as `atelier-g6rp` and `atelier-qr5s`), attributed to its first planner (or `-` if none).
  - `Happened::PlanMerge` (printed as `plan-merge`, distinct from item `merge` so `garden.md`'s `$4 == "merge"` counter never miscounts plans as items) when a first-parent merge onto `base` brings a mission record onto `base` as open/agreed (or merges a plan amendment).
  - Update `crates/atelier-cli/src/history.rs`, `crates/atelier-cli/tests/log.rs`, and `docs/design.md` ("The log") to format, test, and document both, and add a bounded deadline option (or wrapper) on the Git walk so Desk reads stay bounded (15s).
- Implement `GET /api/repos/{repo}/missions/{id}/history` (M5) in `crates/atelier-desk/src/server.rs` using `atelier_core::log::history` via `Repo::open_committed`, returning structured mission + item actions (timestamp, commit, id, action, thread, detail, skips), cached by repo ref tips, with `ts-rs` types regenerated in `desk/src/api/`.
- **Keep `GET /api/history` and `GET /api/launch` on the existing subject parser in this mission** so `t3-extension/fixture-desk.mjs` (which builds its closed mission with `--allow-empty` commits) and pre-cutover history remain intact with zero edits under `t3-extension/`. File a follow-up item for migrating `/api/history` and `/api/launch` once `t3-extension/` is next opened.

## Sizing

Six focused items, each small-to-medium (1–2 review rounds expected). Zero edits in `t3-extension/`, no record schema version bump, and no live LLM eval matrices required.

## Derisking

- **No spike needed:** Every item modifies well-understood existing modules in `crates/`, `.github/`, `scripts/`, and `skills/`.
- **Checked during round-1 review:** `cargo clippy --all-targets --locked -- -D warnings`, `atelier check`, `scripts/ci-jobs.test.sh`, `evals/agent-factory/test.sh`, and Desk `views`/`types` tests are already green on `master`; `atelier log` runs in 0.4–0.7s on this repository.
- **Main remaining risk:** Existing eval fixtures (`evals/agent-factory/test.sh`) and `node t3-extension/run-tests.mjs` assert exact CLI and Desk behaviors. Every CLI item must run `evals/agent-factory/test.sh target/debug/atelier`, and `atelier-js4a` must run `node t3-extension/run-tests.mjs` and `desk/`'s `pnpm e2e` locally before submitting.

## Risks and unknowns

- **`output.rs` / `say.rs` merge churn:** Items `atelier-h6ij`, `atelier-gqtw`, and `atelier-zc9b` all touch CLI output wording. Running them sequentially avoids repeated rebases.
- **Coordination with `atelier-oiwy` (`atelier-kw8u`):** `atelier-oiwy` pins its own `--ref` and `EVAL_ATELIER` binary copy when it resumes on 2026-11-23; still, this mission leaves `roles/reviewer.md` untouched, and the lead should note `atelier-h6ij` / `atelier-zc9b` for `atelier-kw8u`'s lead.
- **Coordination with `atelier-dh7a`:** `atelier-dh7a` is agreed on `master` (not yet started) and touches `plan.rs`, `output.rs`, `garden.md`, and `lead.md`. `atelier-ww7w` should land first (or its lead should notify `atelier-dh7a`'s lead before `dh7a` starts); `atelier-gqtw`'s drop already checks for newly added item records on the dropped branch so `atelier-u6oy` integrates cleanly.
