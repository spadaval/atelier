## Finding 1: one-git still fails after x5al because the Desk build script spawns git
Recommendation: fix now

Why (mission.md:33-37) lists four `git` spawn sites in three crates: `atelier-app/src/git.rs`, `atelier-records/src/at_commit.rs`, and the Desk's `fetch.rs` and `stop.rs`. `git grep 'Command::new("git")'` on this commit also hits `crates/atelier-desk/build.rs:10`, which is not under a `tests/` directory. That file stamps `ATELIER_DESK_BUILT_FROM` from `git rev-parse HEAD` at compile time (`build.rs:1-29`).

Success criterion one-git (mission.md:75-77) and atelier-x5al Done when (item.md:29) both require that, outside `tests/`, `Command::new("git")` occur in one source file, `crates/atelier-core/src/git.rs`. x5al's In list (item.md:38) is that file, the forge module, `at_commit.rs`, Desk `fetch.rs` and `stop.rs`, and CLI `git.rs` where a helper moves. `build.rs` is not in In, and Out (item.md:40) names hooks, merge's `sh`, notify, the T3 client, and tests, not this spawn.

After x5al as scoped, two non-test source files still spawn `git`, so one-git is false and Outcome's "every `git` call in `git`" (mission.md:46) is false. Either put `build.rs` in x5al and route that spawn through the git module, or exclude compile-time HEAD stamps from one-git and from the Why's count of spawn sites.

Allow those diffs (crate-name lists, fixture paths) in nothing-changed and in ni3d's test-diff rule, and name the files.
