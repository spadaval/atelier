## Goal

Make the one reviewed change after which the tree holds only the new tool, and put everything the cutover will run under review before it runs. After this change merges, the tree's binary cannot read this repository's records, so the cutover (atelier-wd1i) follows at once. That is why this item stops at an approval on its branch: it merges only once Sumeet has named the time.

The change has two parts on one branch. The switch deletes the old workspace and moves the new one from `next/` to the repository root, with CI and the release build following. The cutover kit, under `scripts/cutover/`, is the runbook, its rollback, the text each repository's `AGENTS.md` gets, and the one workflow another repository needs replaced. The rollback is tried in sandboxes at every point the cutover can stop before anyone relies on it.

### The cutover kit

- [ ] `scripts/cutover/cutover.sh` runs the cutover as the steps below, which this item also writes into `docs/strategies/redesign-architecture.md`, Transition, part 4, in place of what is there. It stops at the first failure and says which step failed and what `rollback.sh` will undo. It keeps a journal in its state directory, and writes each entry before the change it describes and marks it done after: each conversion it starts, with the directory and the base commit it starts from; each commit it makes; each push, with the ref's old and new commits; each ref and checkout it moves and from where; each hooks directory it copies; and what it installs, stops or disables. Run again after a stop, it picks up from the journal, and it settles an entry that was started and not marked done by looking at the state itself: whether a push happened is read from the remote's tip, never assumed. Everything outside the script that it touches comes from one settings block at its top or the environment, with this host's values as defaults: the repositories' paths and base branches, the Git remote, the install command and root, the skill checkout, the `systemctl` and `gh` commands, T3's database, and the state directory. The trials run the same script with those pointed at a sandbox.
  1. **Preflight**, which is also a command of its own, `cutover.sh preflight`, so that it can be run before the switch merges. It stops unless all of this holds in each repository: every worktree is clean; the base branch is at its remote's tip; no item is in progress, as the installed old binary reports, except that before the switch has merged exactly atelier-u1ko may be, and after it none; and no T3 thread other than the one running the script (its own `T3CODE_THREAD_ID`) is running in the repository, read from T3's database with one read-only, bounded query. If that cannot be read, it stops and prints the hand check that answers the same question, and continues only when told the check was made. It lists, as information, each unmerged local branch, whose reviews the conversion does not carry, and each worktree that is not on the base branch. Then it records in the journal each repository's base commit and what each worktree has checked out, copies each clone's Git hooks directory aside, and records the installed binary's version and hash, the skill checkout's commit, and whether `atelier-serve` is enabled and running.
  2. **Convert atelier**, in the worktree that has `master` checked out: run the converter, replace `AGENTS.md` with the reviewed text, move `skills/agent-factory-next/` to `skills/agent-factory/`, write the harness hook settings the new `setup` writes, and commit. Run `--verify` and the tree's `atelier check`.
  3. **Install.** The install command, by default `cargo install --path crates/atelier-cli --locked -j 4` from `master`; `atelier setup` for the Git hooks and for each harness; move the skill checkout forward to `master`; stop and disable `atelier-serve`, since the new binary has no `serve`.
  4. **Push `master`** with `ATELIER_SKIP="cutover conversion"`, by plain `git push`.
  5. **Each of the other four repositories**, converted in a fresh clone of its base branch: convert; replace the process section of `AGENTS.md` and, in astromech, the workflow that runs Atelier; write the hook settings; commit; run `--verify` and `atelier check`; push with the same skip.
  6. **Bring each real clone onto the converted base**, the four and atelier alike, so that the directory agents start in is on new records. Fetch, and move the base branch to the pushed commit: a fast-forward in the worktree that has it checked out, else an update of the ref. If the clone's main worktree is not on the base branch, switch it to the base branch, or, where another worktree has the base checked out, detach it at the base's tip; the journal holds what it was on, and the branch it left is kept. Run `atelier setup` for the Git hooks. Other worktrees are not touched. Each one still on an old-layout branch is printed with its path and branch: `atelier` and the hooks refuse there until its branch takes the converted base, and the README says how.
  7. **Accept**, before anything is closed: in each repository's main worktree and base worktree, `atelier check` passes, `atelier status` runs, the count of items and missions equals the count the conversion printed, and the base is at its remote's tip; `atelier --version` is the new tool; the skill checkout's `skills/agent-factory/SKILL.md` is the new text; `atelier-serve` is stopped and disabled; and CI on atelier's `master` has passed on the conversion commit with the tree's binary, waited for with a bound and read through `gh`. A failure here is a stop like any other, and the rollback undoes it.
  8. **Close** atelier-wd1i with `atelier close`, the first act the new tool records, and push the commit it makes. Past acceptance the cutover is not rolled back for a later doubt: a failed push here is retried by running the script again. `rollback.sh` still undoes this step correctly, as the trials show.
  At the end it prints, for each repository, the conversion commit, the count of items and missions, `--verify`'s result, the count of relative links that still resolve, where each worktree was left, and how long each step took.
- [ ] `scripts/cutover/rollback.sh` undoes what the journal says was started, newest first, and is safe to run twice. In order:
  1. The hooks directories go back, since the new hooks would refuse the pushes below and would call commands the fallback lacks.
  2. For each repository, the remote's base tip decides what its conversion needs, read with `git ls-remote` and compared with the commits the journal recorded. If the remote is still at the recorded base, nothing was published: a fresh conversion clone is deleted, and in atelier's base worktree the base is reset to the recorded commit and the paths the conversion writes are cleaned, tracked and untracked, leaving files that were there and ignored before. If the remote holds the runbook's commits, each is reverted newest first in a clone of the remote's tip and the reverts are pushed, so a close commit is undone before the conversion beneath it. If the remote's tip is neither, the rollback stops for that repository without resetting anything and says what it found.
  3. Each real clone is then brought to where its remote now is. Where nothing was published its base is the recorded commit. Where reverts were pushed its base is moved to the revert's tip, whether the clone had already taken the conversion or was still at the recorded base. Each worktree is put back on what the journal says it had checked out; one that had the base checked out is at the base's tip.
  4. If step 3 of the cutover had started: the fallback release is reinstalled from the pinned `v0.4.0` archive with its checksum checked, its `setup` is run, the skill checkout is moved back, and `atelier-serve` is enabled, started and checked to answer.
- [ ] **The rollback is tried in a sandbox at each point the cutover can stop**, and the Report says for each what was stopped, what `rollback.sh` did and what was compared afterwards: (1) a conversion that fails part-way, before its commit, by the script's own path: the rule that finds a repository's `AGENTS.md` section matches nothing; (1b) `--verify` failing after step 2's commit; (2) after step 2's commit; (3) part-way through step 3, with the binary installed and the hooks not; (4) after step 3; (5) after step 4; (6) a second repository's conversion in step 5 committed and not pushed; (7) in step 6, with some clones brought onto the converted base and others not; (8) a failure of step 7, with CI on the conversion commit reported as failed; (9) after step 8's commit and before its push; (10) after step 8's push; (11) a push in step 4 that the remote accepts and that then reports failure, before its journal entry is marked done; (12) a stop in step 5 after one product repository's conversion is pushed and before any real clone has fetched it. What "restored" means is stated and checked the same way every time. Where nothing of a repository was pushed, its base is the recorded commit. Where something was pushed, its base holds one revert per pushed commit, its tracked tree is identical to the recorded commit's tree, and local and remote tips agree. In every repository each worktree has checked out what it had, or the base's tip where it had the base, its hooks directory is identical to the copy, no file the conversion wrote is left behind, and the old binary's `check` passes on the old records. The sandbox's installed binary is the fallback, and the skill copy is at its old commit.
- [ ] **The sandbox is the five repositories as they really stand**, in what matters: clones of all five with their remotes pointed at local bare repositories and Git limited to local files, as `rehearse.sh` does it; a scratch install root; a copy of the skill checkout; doubles for `systemctl`, `gh` and T3's database. One clone's main worktree is on a feature branch with a second worktree on another branch, as one real repository is; one clone's main worktree is detached with its base checked out in a linked worktree, as atelier is; one clone has a Git hook of its own, which is back after a rollback. The preflight is shown to pass with only the script's own thread running and to stop with another thread running; and to pass before the switch with atelier-u1ko in progress and stop with any other item in progress. One full run with no stop ends with step 7 passing in every main and base worktree and the sandbox's copy of atelier-wd1i closed.
- [ ] **A later host adopts what this host converted**, by the same script: `cutover.sh adopt`, for a host that still has the old binary, the old skill and old records, when the remotes are already converted. It is run from a fresh clone of this repository at its converted `master`, made for the purpose, which is where the host gets the reviewed script, the new tool's source and the new skill without moving any checkout it works in. In order: the preflight, with each base allowed to be behind its remote and never ahead of it; the new binary installed from that clone, by default `cargo install --path crates/atelier-cli --locked`; the skill installed by the command the settings give, since hosts install it differently; `atelier-serve` stopped and disabled where the host has it; then step 6 for each repository; then step 7 without the CI check, with the count of items and missions read from the adopted commit by `atelier check` and printed, not compared with a conversion. It converts nothing, pushes nothing and closes nothing. `rollback.sh` undoes it from its journal and pushes nothing: hooks, refs and worktrees back to what was recorded, the fallback reinstalled, the skill and the service as they were. One sandbox trial plays a second host that is still before the switch, with its old service running, against remotes the full run converted, and one rolls it back. The Transition's "The work host" paragraph says this in place of "by the same runbook".
- [ ] **Text for each repository's `AGENTS.md`**, under `scripts/cutover/agents/`. For atelier, the whole file: the new commands, the merge policy as the new tool applies it, and how a mission is read until the Desk has its page (`atelier show <mission>`). For the four product repositories, one process section each, written here and holding nothing of theirs: how work starts (`atelier status`), and how the base reaches the remote, since none of them configures a forge: after `atelier merge`, `git push` of the base, which the pre-push hook checks. The runbook finds the section to replace by rule, not by quoting the repository: the sections of its `AGENTS.md` that name a removed Atelier command. It stops if a repository has none, or more than the number recorded for it. The Report gives, per repository, the count of sections and lines replaced and nothing else. No text sends anyone to a site page, names a removed command or record path, or tells an agent to commit after `ready`, `drop`, `close` or `lead`.
- [ ] **A replacement for astromech's workflow that runs Atelier**, under `scripts/cutover/`: it installs Atelier from the commit of `master` the cutover converted, which the runbook writes into it, and runs `atelier check`. It runs no `doctor` and no `land`. No other repository's workflow names Atelier.

Settled in this plan:

- **One branch.** The switch and the kit are one item and one pull request, because the runbook installs from the tree the switch leaves and its trials need both.
- **Acceptance before the close.** The protocol closed the cutover item as its last step and left the checks for afterwards, which made a state no rollback covered. The runbook now proves the cutover in step 7, CI included, and closes in step 8. A stop up to and including step 7 is rolled back; past it the cutover has happened and what breaks is fixed forward in step H.
- **Rollback by journal and by what the remote holds.** The journal says what was started, entry before act, so nothing the runbook changes is unrecorded. What was published is read from the remote, because a push can succeed and report failure. A published commit is undone by a revert, never by rewriting published history, so its base ends on a new commit with the old tree, and every real clone is brought to that commit.
- **Checkouts.** A repository's main worktree is where sessions start, so it ends on the converted base. It is switched only when clean, which the preflight has checked, and the branch it was on is kept. Other worktrees are left as they are and refuse until brought forward, which is the safe direction.
- **The work host** does not convert: its remotes are already converted. It adopts, with the same script's `adopt` command.
- **Version.** The new tool is `0.5.0`. Nothing is released by this item. astromech's CI installs from a commit, as it does today, and the install command is a setting, so a host can install from a release once one is cut.
- **No forge for the product repositories.** Their converted `config.toml` names none, as today, so `submit` opens no pull request there and `merge` pushes nothing. Their `AGENTS.md` text says to push the base with Git. Giving a repository a forge is a reviewed change to its config, later, if Sumeet wants pull requests there.
- **Hook settings.** `atelier setup` for a harness writes into the repository it runs in, so each conversion commit carries those files, and undoing that commit restores them.
- **Not merging.** Under the old tool, `atelier merge <id> --push` pushes the branch and opens its pull request before it judges the gates, and merges if they all pass. So it is run, without `--wait`, only straight after `atelier merge atelier-u1ko --check` has shown the review gate refusing for the committed head, and only while no reviewer of this item is working: before each review round is requested, and after any commit that changes code, which makes an earlier approval stale. A planning approval, or an approval of an earlier commit, is not a current one and does not let the merge through; `--check` is what tells. Once a current approval of the head exists, no `atelier merge` command is run by anyone but the orchestrator, at the time Sumeet names.

- **The Desk's freeze.** The Desk's mission merges into `next/` until this item is started. The freeze then lasts until the cutover has run, which is until atelier-wd1i is done: while this item is in progress, and after its merge marks it done, for as long as atelier-wd1i is not done. In that time the Desk's mission starts and merges nothing that touches `next/` or, after the switch, `crates/`, the root `Cargo.toml` or the CI and release workflows. Its check before each start and each merge is therefore "atelier-u1ko is not in progress, and atelier-u1ko is not done while atelier-wd1i is open"; a check of whether either is in progress would let work through between the switch's merge and the runbook. So the branch is cut from a `master` that already holds whatever the Desk merged, and no sync is expected. If Sumeet names a time more than a day away, the mission's planner may lift the freeze for the interval. It is put back before the branch is brought up to date: the planner confirms the freeze, then the branch takes `master` with `atelier merge --sync`, and its CI run, the root workspace's checks and `scripts/cutover/rehearse.sh` are run on that head, whose commit the mission's note names as the one the proofs cover. Nothing the Desk touches merges after that until atelier-wd1i is done.

`AGENTS.md` asks for `scripts/smoke-repos.sh` before review of a command change; this change deletes that script, so it is not run.

Expected size: the move is about 50 renames and 290 deletions with a dozen files changed around it; the kit is 800 to 1,200 lines of shell, 200 of text, and the trials' harness beside it.
