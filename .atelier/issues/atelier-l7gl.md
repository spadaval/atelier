## Goal

Stop every pull request from building all six release targets. `dist-workspace.toml` has `pr-run-mode = "upload"`, so each PR runs about three macOS release jobs alongside CI's macOS test job, and GitHub runs at most five macOS jobs at once. Switch to `pr-run-mode = "plan"` so PRs only run `dist plan`, and tag pushes still build and publish.

## Done when

`dist-workspace.toml` has `pr-run-mode = "plan"` and the comment above it describes plan mode; `.github/workflows/release.yml` is regenerated by `dist generate` at the pinned `cargo-dist-version` with no hand edits (running `dist generate` again leaves it unchanged); the PR's Release run runs only the plan job; and in docs/strategies/release-distribution.md, S2's sentence about pull requests and its "Shown by" line say PRs plan the release (no artifact build or upload), with a dated change note naming Sumeet's 2026-11-04 request as the authority for the S2 change.

## Context

Requested by Sumeet on 2026-11-04 as a follow-up to the release validation atelier-g6a1, which used the PR upload runs as S2 evidence; do it after that validation. Rewording S2 changes a success criterion; that request is the human authority for it. The strategy's Authority section lets the orchestrator change `dist` settings.
