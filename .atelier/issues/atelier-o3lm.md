## Outcome

Every atelier view, confirmation, and error tells its reader what they came to learn, and what to do next, in one dense screen. Today readers often have to run a second command or pipe the output through head, grep, or sed. A view that names a blocker, owner, finding, or receipt says what it is and where it stands. A mutation confirms the resulting values. A gate ends in a verdict, and each failure carries its own fix. Sibling views share one vocabulary and one row shape. No command crashes when piped, and none reports something as valid that it is not.

## Success criteria

- S1: `docs/product/human-cli-output.md` defines the output contract: one row grammar, one footer form (`Next`), counts and plurals, the `--quiet` token per command, the verdict line for gating commands, and the confirmation shape for mutations. Every read view, mutation, and gate follows it, shown by rendering tests.
- S2: Where a view names another record (blocker, parent, mission, owner, finding, disposition, receipt), it shows that record's status and title, or its state mark, on the same screen. `work mission` shows what holds the mission up, and `issue show` shows branch, review, and proof state. Shown by fixture tests that include cross-mission and unassigned blockers.
- S3: Every refusal and error names the record, states the cause once, and ends with a runnable recovery command that uses real IDs, never `<issue-id>` when the ID is known. Shown by tests over land, merge --check, start, transition, check, and not-found paths.
- S4: No silent wrong output: piping to `head` exits cleanly, `bundle preview` rejects what `apply` rejects, captured evidence keeps the failure tail, filters never return an empty result for a valid short ID, and nothing truncates without naming the flag that shows the rest. Shown by tests.
- S5: Rerunning the transcript pipe analysis over agent sessions recorded after the mission shows that `status`, `work *`, `issue show`, `merge --check`, `land`, and `evidence record` are piped through head, grep, sed, or tail in under a third of runs. When the audit was filed (2026-10-16) the rate was about 75% for read views. Shown by a dated note on this mission with the counts.

## Background

This mission was filed from a six-surface audit of the CLI on 2026-10-16: work views, status/land/init/setup, issue commands and start, review/evidence/merge, bundle/check/prune/policy, and help/errors/cross-cutting consistency. The audit ran every command against this repository and against fixture clones, and mined Claude Code transcripts from this repository and astromech. It built on ADR 0022 (atelier-bw0b: status orients, output is dense Markdown, never JSON for agents, routine piping means a view is missing) and on the human's review of `work missions` and `work mission`. Items already filed under atelier-1w8c (sdb0, deyy, 7u4o, ihns, 7n5u) and in backlog (fdxj, fpxc, majk, stsa) are not repeated here. Items that extend them say so, and are blocked by them when both rewrite the same renderer.

The items are all in backlog, labelled `cli-output` plus an area label (work-views, status, land, setup, issue-commands, start, review, evidence, merge, bundle, check, prune, policy, cross-cutting, help). The orchestrator plans increments from them. A natural first increment is the cross-cutting contract (the broken pipe, the output contract doc, footers, real-ID hints, --quiet), then one increment per surface.

Transcript-analysis scripts used by the audit: `~/scratch/cli-audit/cc-scripts/` on the audit host. They are not in the repository; commit them before S5 is measured.
