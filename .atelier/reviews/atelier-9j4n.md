Re-reviewed 4ff56376 (single-pass UniqueKeys) at f1704ae1. Value equivalence: compared master's plain BTreeMap<String, serde_json::Value> parse, the two-pass da89a657 version and this branch on about 70 front-matter inputs in a scratch crate pinned to serde 1.0.228, serde_json 1.0.148 (no arbitrary_precision) and serde_yaml 0.9.34. Every accepted input gives an identical map: i64/u64, hex/octal, +1, floats, .nan/.inf -> null (from_f64 like serde_json), 1e400 and 012 -> strings, ~/null/empty -> null, core tags, aliases, '<<', and non-string scalar keys (both use deserialize_str). u128/i128 overflow and nested local tags are still rejected (no visit_u128/visit_enum). Non-mapping and empty front matter fall back to the plain parse, so those results are unchanged. The per-file error still comes from the same 'Invalid YAML front matter in <path>' context. Speed: 60 interleaved release runs of 'atelier check' on the 1,000-issue fixture: master 49.7 ms median, two-pass 71.9 ms, branch 50.7 ms. The test is right: the typed top-level case needs "duplicate key '1'", which the old Value-keyed visitor did not produce, and the nested and top-level cases plus the restored-file pass remain. cargo nextest run --workspace: 648/648 pass locally. Minor differences (top-level local tag now rejected, some error wording, first-error-in-document ordering) are filed as defer atelier-nib3. s3fo and n6zq are dispositioned fix_now against 4ff56376.
