crates/atelier-app/src/record_index.rs:366-374: the cascade filter matches dropped IDs without their kind, so it hides real missing references. `dropped` stores bare IDs and the retain closure ignores the parsed kind. Scenario: two evidence records share ID atelier-x and no issue atelier-x exists. A review targeting issue atelier-x, or an issue that blocks/children/relates issue atelier-x, produces 'reference to missing issue atelier-x' from ensure_issue (lines 436, 454, 490, 514) or ensure_record (538), and the filter drops it. No issue atelier-x ever existed, so that error has nothing to do with the dropped evidence. The same happens with issue atelier-x plus a dropped evidence atelier-x and a 'missing review atelier-x' reference. The error only shows up after the duplicate is fixed. Because validate_review returns early with ?, that review's later checks are skipped too. check still fails on the duplicate, so nothing passes that should not. Fix: store (kind, id) for each dropped record ('issue' for duplicate issues, 'evidence', 'review'), and suppress an error only when the parsed (kind, id) is in that set. Add a test where the reference's kind differs from the dropped record's kind and is still reported. Everything else checks out. Parsing matches both formats (ensure_issue 'Issue S has R reference to missing issue X', ensure_record 'S has R reference to missing K X'). explain_pruned_reference runs in validated() after structural(), so its '; ...' suffix never reaches the filter. retain keeps the order of the remaining errors. from_records and from_project_records still return the duplicate first. The new test covers the cross-kind issue+evidence claim, and it passes.
