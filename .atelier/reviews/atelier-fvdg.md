medium: crates/atelier-cli/src/commands/session.rs:551 (refuse_unresolved_base_upstream called for every push) and crates/atelier-cli/tests/session.rs:5869. The refusal runs on work-branch pushes too, where it protects nothing: check_base_commits (the check that skips an unresolved upstream) only runs when land is on the base itself (session.rs:382); on a work branch an unresolved base upstream makes 'trusted' None, which checks more, not less, and pushing a work branch publishes no base ref. Failure scenario (reproduced with local bare remotes): a repo whose main was pushed with 'git push -u <path> main' (branch.main.remote is a path, the exact case hwfm names) can no longer 'land --push' any work branch: 'land: refused — 1 check (land_push_base_upstream_unresolved)', while the same repo with no main upstream at all passes and pushes; the message also tells the user 'unreviewed main commits cannot be checked before publishing', which is untrue for a work-branch push. Meanwhile the new test exercises only that work-branch path, so the scenario atelier-hwfm reported (on main, an unreviewed code commit, gone or URL upstream, land --push publishes it) has no regression test; I confirmed by scratch tests that the base path is now refused for gone, path, file:// URL, no fetch refspec, remapped fetch refspec, removed remote section, while '.' gives land_push_upstream_mismatch and pushurl/multi-merge still hit land_base_unreviewed. Fix: call the refusal only when the pushed branch is the base (branch == base_branch from the same policy land checked), and move the test onto main with an unreviewed code commit, asserting the remote's main is unchanged for a gone upstream and a URL remote; keep a work-branch case asserting it still pushes.
