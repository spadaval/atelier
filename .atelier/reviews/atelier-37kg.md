Integration branches and stacking are still recommended with no Atelier caveat: references/branches-and-worktrees.md:26-28 ('At most one integration branch per mission... Slice PRs target it'), :33-35 ('Stack only for real dependencies. Base a branch on another unmerged branch'), and procedures/migrate.md:35-36 ('Build on the mission's integration branch'). The only caveat is in references/atelier.md:81-84, which migrate.md and branches-and-worktrees.md do not link to, and atelier.md never says to run 'atelier start' from the base branch. start.rs records the current branch as branch_base when it creates the work branch, and 'A recorded base is never replaced'. Reproduced in a scratch repo: start task A from main, then while on task/A create and start task B -> B records branch_base task/A; after close+commit, 'atelier merge B --check' fails ('merge requires base policy for task/<A> ...') and 'atelier land' fails (land_base_mismatch). An agent following the stacking or integration-branch guidance in an Atelier repo ends up with an owner it cannot merge without hand-editing front matter. This conflicts with the requirement that the skill not mislead agents about integration branches. Fix: in branches-and-worktrees.md and migrate.md, say that in Atelier repositories integration branches and stacked branches are not supported yet (see atelier.md, atelier-w0su); and in atelier.md, say to run 'atelier start' from the base branch.
