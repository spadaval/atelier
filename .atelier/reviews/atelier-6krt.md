Reviewed git diff master...HEAD (b5dc2f57) against atelier-2hh8 and standards.md. Contract pass: on cfg(target_vendor = "apple") Requests::pair sets SO_NOSIGPIPE on atelier's request end, and the choice is commented next to the socket setup. unsafe/SAFETY: setsockopt gets a live fd borrowed from the UnixStream, a pointer to a stack c_int that outlives the call, and its exact size; the SAFETY comment states those conditions correctly; errno is read straight after a nonzero return. cfg: target_vendor = "apple" matches std's own gate and libc defines SO_NOSIGPIPE for all Apple targets; Apple is cfg(unix) so the cfg(unix) libc dependency covers it. Only atelier's end: SIGPIPE is raised on the writer and SO_NOSIGPIPE is per socket; atelier writes only to its end, the child's end is git's stdin and stays untouched, and the pair is CLOEXEC so atelier's end is not leaked into the child. Error handling: setsockopt failure becomes an anyhow error with the same context as socketpair failure, using ? on a fallible boundary per standards. Linux: the new code is entirely cfg-gated; the Linux path is byte-identical. No new test: acceptable, since the behaviour can only be exercised on XNU and the existing bsyn piped_output test covers it when the suite runs on macOS; there is no macOS CI.
