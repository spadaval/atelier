crates/atelier-cli/src/commands/git.rs:141-155 (follow-up to atelier-3su5, which is only partly resolved). Coverage is now limited to approvals and exemptions of done owners whose branch_base is this base, but the pin can still be any commit, including base HEAD after a direct code commit. Any owner that was merged earlier still qualifies, and the repo has many of those. Reproduced: start, close, self-trivial and atelier merge an owner, then push. Commit code directly on main: land exit 1. Then run 'atelier review trivial <that merged owner> --identity A' on main and commit it: land exit 0, 'Base commits: 1 unpushed record-only commit(s) outside review'. atelier start's new check passes the same way. This is routine practice here: master's ab146920 records a trivial exemption for done owner atelier-9vq3 (branch_base master) pinned at master commit 995d4282, which itself edits docs/product/work-model.md. docs/product/reviews-and-merge.md:107-110 says such coverage 'is what atelier merge integrates'; that is false for pins recorded on the base. Suggested fix: exclude owners that are already terminal in the upstream's copy of their record (a pushed merge cannot vouch for later base commits). Also bound each pin's coverage to commits after the owner's fork point (the parent of the commit that first recorded workflow_branch), and require the pin's review record to be introduced by a commit the pin does not itself contain via the base (or equivalent). Add a test that merges and pushes an owner, then records a trivial exemption for it on main.
