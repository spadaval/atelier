crates/atelier-cli/src/commands/session.rs:282-290 treats every commit reachable from ANY approval or trivial-exemption pin in the index as reviewed, regardless of target, author, branch, or whether merge would accept it. Two ways direct base code passes without review: (a) the author records 'atelier review trivial <any issue> --identity <self>' while on main (review append pins HEAD and only requires it be an ancestor) and commits it; reproduced: direct code commit on main -> land exit 1; then trivial exemption for an unrelated, unstarted issue -> land exit 0 'Base commits: 1 unpushed record-only commit(s)'. This repo already records trivial exemptions on master (ab146920), so it is a routine action, not a contrived bypass. (b) following land's own advice ('atelier start <id>') while the direct commit is still on main forks the work branch on top of it; the reviewer reviews master...branch, which excludes that commit, yet the approval pin contains it, so after merge it counts as covered. docs/product/reviews-and-merge.md:108 states that a covered commit 'came through review', which is false in both cases. Fix: only count a review as coverage if its target owner has workflow_branch with branch_base == base, and cover only the range from the branch fork point (parent of the commit that first recorded workflow_branch, as review_gate::original_independent computes) to the pin, i.e. rev-list <pin> ^<fork-parent>; alternatively require the pin to be one that atelier merge's review_gate would accept. Add tests for both cases.
