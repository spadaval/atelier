Read unmerged_done_label (crates/atelier-cli/src/commands/git.rs:368-401) and its three callers (session.rs prime, status.rs owner_row, git.rs branch_lines_for). The fallback runs only when the base resolves and has no copy of the record. It needs refs/heads/<branch> to resolve, the committed record there to have the claimed status, and that tip to be an ancestor of the base, so the done record was in the base's history. A done claim committed after the merge moves the tip out of the base, and an uncommitted close leaves a non-done tip, so neither says merged. A base deleted for another reason still had the done tip merged, so merged is historically true. Only a merge that threw the branch's record away (e.g. -s ours) and a later delete could say merged falsely, which is contrived. Detached HEAD: prime passes 'detached HEAD', which matches no owner; status returns None. A branch or base that does not resolve, or a record that fails to parse, gives not merged (conservative). The false negative when post-merge commits sit on the kept branch matches the requirement's 'tip in the base' wording. prune.rs remove_canonical_records renames the issue, evidence and review files out of the working tree for the user to commit, so the test's git rm of the owner and reviews plus a commit is equivalent. The targeted test passes. One test-gap finding, deferred.
