Reviewed git diff master..HEAD (e3ac5198) against Goal, Done when and Scope. Scope: the one fix is in main.rs, cfg(unix) libc::signal(SIGPIPE, SIG_DFL), with no per-command patches. libc is a unix-only target dependency that was already in Cargo.lock. The unsafe block is the only unsafe in the crates and carries a SAFETY comment. On non-Unix the function compiles to a no-op and the test's libc use sits under cfg(unix). Test: piped_output passes at HEAD. In a scratch copy (git archive HEAD) with the restore_default_sigpipe() call commented out, it fails on stderr containing the panic. Its output is about 150KB, more than a pipe buffer, so it is deterministic. Real repo, head -1: review list goes from 101 plus a panic to 141 with empty stderr. issue show, evidence show and work mission were 0 with either build. Pipe writes: std resets SIGPIPE in spawned children, so child dispositions are unchanged. git archive|tar runs child to child. The only production write to child stdin is ObjectReader (finding atelier-spnf, defer). Mutating commands: a failed stdout write used to panic at the same point where SIGPIPE now kills. Nothing catches the panic or handles stdout errors gracefully. The mutation lock is a file lock the kernel releases. The only lost cleanup is TempDir drops under the gitignored .atelier/runtime. Not run: the full nextest suite (the author's receipt atelier-j4ky stands for that), test-hooks, a Windows build, and evidence record or issue create on outputs bigger than a pipe buffer.
