medium: crates/atelier-app/src/review_gate.rs:210 (approval_accepted) vs :761/:487 (merge review.current): land and merge judge approval independence from different author sets. merge's review.current takes authors from the fork point (base commits merged into the branch excluded); approval_accepted uses original_independent, which walks from the branch start's parent to the event and so counts the authors of base commits the branch merged in. A reviewer who authored reviewed work on the base, merged into the branch after it started, is independent for review.current but not for land or claims.reviewed. Reproduced in scratch repos under both strategies, regressions against master c90eb4d1, where both cases merge and land: (1) base commit by git author Reviewer, git merge main into the branch, close, approve as Reviewer: merge --check fails only claims.reviewed (review.current passes), and its advice to record a fresh independent approval cannot work for that reviewer; land on the base refuses too. (2) Approval by Lead, owner close, a later code commit, then approval by Reviewer: merge --check passes, merge integrates, then land on the base refuses with land_base_unreviewed on the code commit. That is the post-integration refusal uw4x exists to prevent, and it contradicts the 1ztv decision note and the Close Reason that land's rule matches what merge requires of an approval. It cannot happen in this repository today, because reviewer identities are never git authors, but it is a gate regression for any repository whose human reviewers also commit. Fix: compute one author set for both. Make original_independent skip the base commits merged into the branch, as work_edges does for currency, or have review.current use approval_accepted. Add these two cases to a_close_after_approval_is_covered_by_merge_and_land_alike.
