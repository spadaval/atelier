Checked: issue (parse_issue_record) and evidence (parse_evidence_record_file) both go through split_front_matter -> parse_front_matter. Reviews use a derived Front struct with deny_unknown_fields, and derived serde already rejects duplicate fields there. I confirmed this for top-level target, the event tag, and the nested recommendation ('duplicate field'). review_gate.rs parses into serde_yaml::Value, which rejects duplicates in 0.9. Epic migration is a line-based rewrite whose output is parsed again. bundle and session use only the body. There is no index cache. In the visitor, tags reach visit_enum and are checked, and the second parse rejects tags anyway. Aliases are replayed and checked. Merge keys stay a literal '<<' (serde_yaml does not merge), and a repeated '<<' is rejected. Multi-document input is rejected by from_str, and the split on '---' already excludes it. Error ordering is unchanged: the per-file error is an 'Invalid YAML front matter in <path>' error from the same place as before, and its message names the key path, line and column. Proved by the check, 'evidence show' and a review on a cloned repo. The test covers nested relates id and top-level duplicates, then checks that the restored file passes. With the UniqueKeys line disabled, the test fails ('nested: Lint passed.'). Evidence atelier-0do3: cargo nextest run --workspace passes. Two defer findings filed: key-type coercion gap and double-parse cost.
