Reviewed git diff master...HEAD at ceb96d6e (human_output.rs ItemLine::fields/ItemField, render, render_wrapped and the new narrow coloured row test) against the item's Done-when, the Item Line section of docs/product/human-cli-output.md and quality/standards.md. render is equivalent to before: the same fields in the same order joined by single spaces, painted with the same styles, including empty title or status. render_wrapped counts width on unpainted pieces, so ANSI codes do not count. It breaks only between fields and title words, and hard-wraps a field only when that field alone is wider than the line. Each piece is painted with its field's style. Full cargo nextest run -j 4 at HEAD: 750 passed. I built master (b9bd6d50) from git archive and compared redirected output on work ready, work mission atelier-o3lm, status, work missions, work blocked, work, issue show and issue list. Without COLUMNS it is byte-identical. With COLUMNS set from 16 to 90 it is identical except work mission atelier-o3lm at COLUMNS 20-24, where master split '✓ | done' across lines and HEAD keeps '✓ done' whole, which is the intended fix. Coloured views through a pty (script) at COLUMNS 20/24/30/40 keep the status and priority colours on wrapped rows, and no visible row exceeds the width. status's key-value rows (Owner, Mission) are not wrapped and are uncoloured both before and after, so they are out of scope here. The test fails against the old plain wrap: it asserts the escape codes, whole tokens at widths 12-80, width bounds, no lost characters and the exact layout at 40. Not checked: real terminals other than script, or wide/combining characters, since display_width counts chars (pre-existing). One DEFER finding: COLUMNS also applies to redirected output.
