crates/atelier-cli/src/commands/git.rs:136-152 (check_base_commits): the new early return skips every base-commit check whenever main@{upstream} lacks the workflow policy. That covers ordinary code committed on a local base that already has Atelier, not just the install. This is a regression against master and breaks the constraint that relaxing gates must not let unreviewed code onto a base that has Atelier. Reproduced in /tmp/rv40i6/a: upstream main has no policy, then on main run atelier init, commit, and commit a code change ('unreviewed code' to app). The branch binary's land passes with 'Base commits unchecked: ... these commits install Atelier'. The master binary refuses with land_base_unreviewed for that commit, because the old per-commit rule (exempt only commits whose parent lacks the policy) already exempted the install commit itself. The fork setup makes this permanent: main tracks origin/main, the parent repo, which never gets the policy, while the policy lives on fork/main. Every later local base commit then goes unchecked, by land and by atelier start (start.rs:193 uses the same function). The tracker_changes_since side already looks at every copy of the base, so the two sides now disagree. Suggested fix: keep the per-commit gate, and exempt only the commit on the tip's first-parent line (walking from upstream) that first has the policy, plus the commits it brings in. That is the install commit, or the merge of an install branch with its review-fix commits, which is the case the new test needs. Gate every commit after it. Also treat the upstream as having the policy if any local or remote-tracking copy of the base has it, as the branch side does. Add a test where code is committed on the base after the install and before pushing. A small has_policy(repo, rev) helper would replace the three copies of the ls-tree check. Then update the sentences in workflow-configuration.md ('checks nothing until that is pushed') and reviews-and-merge.md ('including every commit made while the base's upstream has no policy yet') to match.
