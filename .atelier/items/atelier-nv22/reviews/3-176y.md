## Finding 2: Keep a settlement's passed rules when its commit also creates an item
Recommendation: fix now

At `crates/atelier-core/src/log.rs:604-615`, the fallback adds `Passed` for a newly created draft item, whose record has no inferred action. `Passed::commits()` is true, so the commit-wide `carries` becomes true and strips the same commit's skips from a different item's `Settle` action, whose `commits()` is false. The source item already has an action, so the fallback adds nothing for it. The source mission then loses the rule entirely when history is filtered to its items.

Reproduced through a successful CLI operation with the reviewed binary:

1. Put an agreed mission `demo-m1ss` and its done item `demo-ab12` on `main`. Give the item an approving review `1-aaaa` with deferred, unsettled Finding 1.
2. In that base checkout, as `p1`, run `ATELIER_SKIP="Ada authorized recording this directly" atelier new "Translate greeting" --from demo-ab12/1-aaaa.1` without `--in`, then execute its printed Git command. The command successfully passes the base-checkout rule and commits the source review and a new draft item outside the mission.
3. The commit contains `Atelier-Skip: Nothing is written in the checkout of the base branch main: Ada authorized recording this directly` and `Atelier-Skip-By: p1`. Unfiltered `atelier log` shows the source item's `settle` line without a skip and the new item's `change` line with the skip. `atelier log demo-ab12` and `atelier log demo-m1ss` show the settlement without its passed rule, and `atelier show demo-m1ss` has no `Rules passed:` section.

Before this round's change, the source settlement was the only inferred action, so `!carries` preserved its skip. The new fallback exposes the draft item's commit but makes the source item's audit incomplete. Preserve skips per affected record, including records whose only inferred action does not satisfy `commits()`, while retaining the existing behavior that avoids repeating a verdict's skip on its companion review line. Add coverage for `new --from` with a source item in a mission and a new item outside it. This is still a commit changing the mission's item, so hiding its rule fails Done when 2.
