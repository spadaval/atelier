## Finding 3: Preserve passed rules for records with no action when another record has one
Recommendation: fix now

At `crates/atelier-core/src/log.rs:598-603`, the fallback runs only when `found` is empty for the entire commit. An inferred action on another record prevents an entry for a changed mission item that has no inferred action. The skip is then attached only to the other record's action, and filtering the history to the affected item or its mission loses it.

Reproduced with the reviewed binary through successful CLI operations:

1. Create an agreed mission `demo-m1ss` with an already-ready item `demo-ab12`, and an unrelated draft item `demo-cd34` outside that mission.
2. Start a backlog branch and run `ATELIER_SKIP="Ada reconfirmed the ready item" atelier ready demo-ab12 demo-cd34 --by ada` as `p1`. Execute its printed Git command, then run `atelier submit` and `atelier merge`. Both records change, and the commit correctly records `Atelier-Skip: demo-ab12 is draft (it is ready): Ada reconfirmed the ready item` and `Atelier-Skip-By: p1`.
3. The unfiltered log attaches the skip only to `demo-cd34 ready p1 draft -> ready`. `atelier show demo-m1ss` has no `Rules passed:` section, and `atelier log demo-m1ss` and `atelier log demo-ab12` omit the bypass commit, even after the backlog branch merges.

`demo-ab12` stayed ready, so changing its ready metadata produces no inferred action; `demo-cd34` moving from draft to ready makes `found` nonempty. This still fails Done when 2 for a commit of the mission's item. Preserve a skip-carrying entry for each affected record even when another record in the commit has an inferred action, and cover the batch command with items in different missions or an unrelated item.
