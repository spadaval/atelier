## Finding 1: Two tests in `filing.rs` run raw `git` on hooked clones without the test binary on `PATH`, failing CI
Recommendation: fix now
At `crates/atelier-cli/tests/filing.rs:331` (`git(&at, &add)` for `git worktree add`) and `crates/atelier-cli/tests/filing.rs:378-381` (`git(&at, &["checkout", "-q", "--detach", &format!("origin/{mission}")])`), the tests invoke `common::git` on clones where `hooked(&hub, ...)` has already run `atelier setup`. The `post-checkout` hook installed by `setup` runs `exec atelier check --hook post-checkout "$@"`, resolving `atelier` from `PATH`. Unlike `run`/`done` (which use `common::sh` to prepend `CARGO_BIN_EXE_atelier`'s directory to `PATH`), `common::git` inherits the ambient `PATH`.

PR #284's `test` job on GitHub Actions failed on `a_drop_names_what_was_filed_committed_or_not_and_its_commands_carry_them` and `a_plan_reviewer_publishes_then_files_on_a_backlog_branch_as_its_brief_says` with `post-checkout: 2: exec: atelier: not found`. Running the compiled `filing` test binary directly with `PATH=/usr/local/bin:/usr/bin:/bin` reproduces both failures locally (5 passed, 2 failed). On hosts that happen to have an older `atelier` installed on `PATH`, those two commands silently run the installed binary in `post-checkout` instead of the binary under test. Run those two checkout/worktree commands with `CARGO_BIN_EXE_atelier`'s directory first on `PATH` (for example through `done`, quoting the worktree path, or a helper in `filing.rs`).
