## Finding 1: Step 4's list command will not find the rolling item
Recommendation: fix now

`atelier list --label` takes one label and tests
`entry.labels.contains(label)` (`crates/atelier-cli/src/main.rs` around
the `--label` flag, `crates/atelier-core/src/work.rs` `narrows_item`).
It does not split on commas. `atelier set --labels` in the same
procedure does.

Step 4 tells the gardener to list with `atelier list --label <label>`
and then keep "those labelled `needs-human,garden`"
([garden.md](skills/agent-factory/procedures/garden.md) lines 139-143).
Step 7 uses the same pair to find the open item, and creates a new one
when it finds none (lines 223-226). The same file's step 1 already uses
the working form, `atelier list --label garden`.

In a scratch repo, an item titled `Garden proposals` with labels
`needs-human` and `garden` was listed by `atelier list --label garden`
and by `atelier list --label needs-human`. `atelier list --label
needs-human,garden` printed "No open work matches."

A gardener who copies the pair into `--label`, as they copy it into
`--labels` two screens later, concludes there is no rolling item and
files a second one. That is the identity collision the title-and-labels
rule is there to stop, and it breaks recovery: unanswered proposals in
the first item look uncovered.

Write the lookup as a command that exists: `atelier list --label garden`
(and with `--done`), then keep the open item whose title is exactly
`Garden proposals` and that also has `needs-human`. Use that same
command in step 7.
