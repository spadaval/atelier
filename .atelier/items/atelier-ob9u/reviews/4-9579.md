## Finding 3: Include uncommitted configuration changes in status
Recommendation: fix now

In crates/atelier-cli/src/commands.rs:128, unsaved gets its entire record
list from planning. That helper at crates/atelier-app/src/repo.rs:513-528
includes only paths under .atelier/items/ and .atelier/missions/, so it
silently excludes .atelier/config.toml. The status acceptance condition
requires every uncommitted record change with its Git command; check
already treats config.toml as one of these changes.

In a valid scratch repository on backlog/probe, I appended a comment to
.atelier/config.toml without committing it. git status reported the
modified configuration, and atelier check printed "Record changes not
committed yet: .atelier/config.toml". atelier status printed neither that
path nor a commit command. Include configuration changes in status's
unsaved list and cover this case with a regression test.

## Finding 4: Identify the unpushed commits in status
Recommendation: fix now

In crates/atelier-cli/src/commands.rs:136-139, unsaved asks rev-list only
for --count, and crates/atelier-cli/src/output.rs:280-284 prints that
number. It never obtains or prints the commits' identities. This falls
short of the explicit Done when line that status names every commit on
the branch that is not pushed, and the design's requirement to list them.

In the same scratch repository, I made two local commits after the remote's
tip. status printed only "2 commits of backlog/probe not pushed to origin"
and a push command. Neither commit's hash or subject appeared, so the user
cannot tell which work is pending from this view. Read and list the
unpushed commits, retaining the push guidance, and test with two distinct
commit subjects or hashes rather than asserting only the count.
