## Finding 1: Publish the harness settings before the base-branch push guard takes effect
Recommendation: fix now

`README.md:393-403` runs `atelier setup` on the base, then `atelier setup claude`, then tells the reader to commit the generated settings file. No branch change is shown before that commit. This leaves an ordinary commit on the base that the newly installed pre-push hook refuses, so the instructions do not get those settings to other clones.

Reproduced with 0.7.0 and a local bare remote: commit and push the initial config on `main`; run the two setup commands; add and commit `.claude/settings.json`; push `main`. The commit succeeds, but the push exits 1 with `main receives only merges made by atelier merge` and lists the settings commit as `not an Atelier merge`. With the README's optional forge configured, the hook refuses every push moving the base instead. This is the behavior in `crates/atelier-cli/src/check.rs`, `pre_push`.

Make the bootstrap order publish the config and generated harness settings before installing the Git push guard, or show how the settings commit travels through an item branch and merge. The setup recipe needs to be usable without an unexplained skip or history repair.

## Finding 2: Explain that ordinary record-only changes require no review
Recommendation: fix now

`README.md:154` says every change is reviewed, and lines 167-170 enumerate two ways past review. The README never explains the ordinary third path: a branch that changes only records, adds no mission and changes no plan merges after validation with no review at all. That is a central part of the branch model, not an exceptional skip.

Reproduced with 0.7.0: on a branch from `atelier start --backlog file-a-draft`, run `atelier new`, commit the draft, then submit and merge. Submit prints `It merges once atelier check passes on the merged tree, with no review`; merge validates the records and succeeds. The product specification's Branches table says the same. As written, a reader is taught a review requirement that this normal command path explicitly contradicts.

Describe the three branch kinds and their merge requirements, including record-only validation and the two independent plan approvals, and scope the independent code-review claim to the changes that require it.
