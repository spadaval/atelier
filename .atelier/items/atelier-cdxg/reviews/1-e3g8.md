## Finding 1: Keep the command deadline active while draining output
Recommendation: fix now

In `crates/atelier-desk/src/bounded.rs:45-61`, the deadline is checked only
until the immediate child exits. The unconditional stdout/stderr thread
joins then have no deadline. A helper process that inherits either pipe
can therefore hold `/api/checks`, `/api/history`, `/api/launch`, or
`/api/motion` open indefinitely even after the main command exits.

I called the actual helper with `sh -c 'sleep 2 & exit 0'` and a 100 ms
limit. It returned success after 2.005 seconds. A helper that never exits
would never return. The timeout path already acknowledges inherited pipes,
but the normal-exit path has the same problem. Bound the whole operation,
including pipe drainage, and add coverage where the direct child exits
while a descendant retains a pipe.

## Finding 2: Keep children visible unless their work is actually shown
Recommendation: fix now

In `desk/src/pages/ThisThread.tsx:313-316`, `others` excludes every child
with any record tie. Having a tie does not mean that the parent holds or
planned that child's mission, so its work is not necessarily drawn in
Holds or Work under this thread. A child on a standalone item, another
mission, or only an earlier record can disappear entirely.

Using the existing fixture host, I sent `host:thread` with
`thread: "thread:unrelated"` and `children: [live.uwxy.id]`. The child is the
known live implementer of `atelier-uwxy`, and its ties read successfully.
The page showed no child and stated, "This thread holds nothing, started
nothing and names no record." Only exclude a child when another displayed
section actually represents it; otherwise show the child and its ties.
Test a parent without its own record ties whose child implements an item.

## Finding 3: Draw the available project home when the roadmap read fails
Recommendation: fix now

In `desk/src/pages/ProjectHome.tsx:238-240`, a failed initial
`/api/roadmap` read leaves `roadmap.data` undefined, so the whole page
remains an eight-row skeleton. Only the missions read has an ErrorBanner.
This hides successfully loaded missions and history and never explains
why the page cannot finish loading.

With the existing fixtures, returning HTTP 500 with
`{"error":"probe: read failed"}` only for `/api/roadmap` produced zero
`.rm-lane` elements and no error text; the page contained just its inbox
count and repository breadcrumb. Distinguish loading from failure, show
the failure, and render the successful portions. Add a failed-roadmap
interface test.

## Finding 4: Show when This thread cannot read what waits on the human
Recommendation: fix now

In `desk/src/pages/ThisThread.tsx:288-290` and `:321`, an inbox failure is
accepted as settled, replaced with an empty list, and never given an error
banner. The page silently drops Waiting on you. The Report says a banner
names a failure of either ties or inbox, but the code renders one only for
ties. In the empty-thread fallback, `components/Glance.tsx:121` also waits
for inbox data indefinitely, leaving the project glance on a skeleton.

I returned HTTP 500 with `{"error":"probe: read failed"}` for
`/api/inbox` while the host named the fixture's live implementer. Its
Holds card drew, but the error was absent from the page. Show that the
inbox is unavailable, preserve the readable sections, and handle the
project-glance fallback the same way. Cover an inbox failure separately
from the existing ties-failure test.

## Finding 5: Cache the branch-time read shared by motion and launch
Recommendation: fix now

`crates/atelier-desk/src/server/views.rs:238-252` runs `git for-each-ref`
on every call and keeps no answer. `/api/launch` calls it at line 180;
`server.rs:727` calls it for every repository on every `/api/motion`
request, outside `Desk::read`'s cache. Even an unchanged repository with
no moving items runs it again. A stalled read therefore costs up to ten
seconds per repository on every poll, and both consumers duplicate it.

This misses the explicit Done when requirement that every read running
`git`, `gh` or `t3_thread_read` has a deadline and a cache. Cache branch
times by repository and commits/refs, or with a bounded lifetime, and
share the result between the routes. Include a repeated-read test proving
that unchanged input does not launch this command again.
