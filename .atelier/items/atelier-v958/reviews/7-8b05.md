## Finding 2: Keep a failed stop publication's result visible after refreshing the page
Recommendation: fix now

`desk/src/components/Acts.tsx:91-103` returns the pending-state note before
rendering `ActOutcome`. The send handler at lines 116-120 calls
`reloadAll()` for any `result: done`, including `stop.rs`'s partial success
when the drop was pushed but `gh pr close` failed. The refreshed mission
becomes `stop_pending`, so that early return hides the response's close
failure and the `gh pr close <branch>` command that finishes the stop.
Setting `sent` afterward cannot restore them.

I reproduced this in two external Playwright cases using the built app and
the existing `World` fixture. The act returned the server's pushed-drop,
failed-close response, and the subsequent mission read returned
`stop_pending`. With a known open PR, the page displayed only the generic
pending note; no act outcome or permission-denied diagnostic remained.
Without a PR mark, it instead displayed "It counts once it is pushed",
even though this act had already pushed the drop and needed its PR closed.
Both assertions that the close failure remain visible failed. Existing
interface tests cover a completed stop and a refusal, but no partial
publication.

Render the act's response alongside the pending state, including its error
and recovery command, and avoid claiming an already-pushed drop still
needs pushing merely because its PR could not be read. Add an interface
regression for a pushed drop whose PR close fails, retaining the pending
status without calling the stop complete.
