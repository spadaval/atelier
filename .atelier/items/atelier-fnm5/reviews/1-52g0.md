## Finding 1: Infer the scheme for all accepted CSS colour formats
Recommendation: fix now

`desk/src/lib/theme.ts:105-125` only recognizes computed `rgb(...)` or `rgba(...)` when inferring the scheme, although `colour()` accepts modern CSS colour functions. Chromium preserves `oklch(...)`, `color(...)` and `color-mix(...)` forms in computed styles, so these backgrounds make `scheme()` return `null` and leave the preceding light/dark state in place. This breaks the documented promise that an omitted `scheme` follows the background's luminance, and leaves the Desk's state colours and native controls in the wrong mode.

Reproduced through the actual host contract: send `{type: "host:theme", colors: {background: "#111111", foreground: "#eeeeee"}}`, then `{type: "host:theme", colors: {background: "oklch(0.98 0 0)", foreground: "oklch(0.1 0 0)"}}`. The background and text update, but computed `color-scheme` remains `dark` and `--run` remains the dark palette's `#62a2f2`. Normalize supported colours to a colour space the luminance calculation handles, and cover light-to-dark and dark-to-light changes using a modern CSS colour in a browser test. The unit test currently expects `isLight("oklch(...)")` to return `null`, so it does not catch the contract failure.

## Finding 2: Nested currentColor bypasses the independent-colour validation
Recommendation: defer

`desk/src/lib/theme.ts:20-31` rejects `currentColor` only when it is the entire value. A valid expression such as `color-mix(in srgb, currentColor 50%, white)` passes and is applied, despite the Report and contract saying colours that refer outside themselves are dropped. In a Chromium host probe, sending this as `background` replaced the previous background instead of preserving it. Its result depends on the Desk's own text colour rather than solely on the host's supplied colour, and the luminance probe can resolve it in a different context from the token's eventual use.

Reject `currentColor` within accepted colour expressions as well, or narrow the documented validation guarantee. This is deferred because only an explicitly trusted parent can supply it, and it grants no write, navigation or network capability.
