## Finding 1: Show waiting questions to eligible deciders after their review has finished
Recommendation: fix now

In crates/atelier-cli/src/output.rs:77, the new question guidance runs only when entry.next is TakeOver. A thread that reviewed an earlier round has no next act once that review is done, even though it holds no current role and may decide a later question unrelated to its findings. Such a thread still loses the question and receives the instruction to stop. This misses the second Done when line and the product page's promise to show unanswered questions to a thread holding nothing on the item.

Reproduced through normal commands: t1 starts and submits demo-ab12; r1 reviews it and records verdict changes; t1 runs atelier escalate "Which output format should be supported?" without --finding. Running status as r1 shows no question or decide command and ends with "Your review is done, and nothing on this item is yours to do. Say so to whoever started you, and stop." Running atelier decide demo-ab12 "Support plain text." as that same r1 succeeds. The caller's earlier review does not disqualify it from deciding a question with no finding.

Show the unanswered questions and the applicable decide guidance based on the caller's current role and decision eligibility, including finished reviewers, rather than only when offering TakeOver. Preserve the existing prohibition on offering those reviewers a take-over. Add a regression using the sequence above.

## Finding 2: Preserve wrapped text beginning with an issue reference
Recommendation: fix now

In crates/atelier-records/src/body.rs:329, !text.starts_with('#') treats any hash-prefixed continuation as a heading. A reference such as #123 is ordinary Markdown text, so a checklist item wrapped before that reference is still truncated. The parser then drops every remaining continuation of that item as well. This leaves the fourth Done when line unmet for a normal kind of wrapped text.

Reproduced with this Done when entry:

```markdown
- [ ] The output links to
  #123 and explains the fix.
```

The built binary prints only "[ ] Done when: The output links to". It should print "[ ] Done when: The output links to #123 and explains the fix." Recognize actual heading syntax, consistent with the heading handling in document.rs, instead of rejecting every leading hash, and cover this case in the parser and status tests.
