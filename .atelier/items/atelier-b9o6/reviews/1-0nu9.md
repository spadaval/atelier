## Finding 1: Malformed judge replies abort grading instead of failing their questions
Recommendation: fix now

In evals/agent-factory/harness/judge.py:266-276, candidate extraction and
answer indexing can throw before an unknown answer is produced. Calling
`parse_answers('{"answers": [', questions, given)` raises
`ValueError: substring not found` because `rindex("}")` is unconditional
once an opening brace exists. A complete JSON reply of `{"answers": 7}`
raises `TypeError: 'int' object is not iterable` instead.

These exceptions propagate through run.py:323 and out of run_one before
result.json is written. A truncated or malformed model response therefore
loses the run's result and can terminate the matrix, rather than failing
the graded questions with a reason as Done when requires. Validate the
response structure and make malformed replies produce unknown answers with
their parsing reason. Cover both truncated JSON and a wrong answers type
through the harness, without a model.

## Finding 2: A graded pass is accepted without a supporting line
Recommendation: fix now

In evals/agent-factory/harness/judge.py:285-292, a missing or invented
`line` leaves the answer as pass. verdict at :308-310 checks only that
answer, ignoring line_found. With one graded question q and otherwise
passing facts, both `{"answers":[{"id":"q","answer":"pass"}]}` and
the same response with `"line":"invented evidence"` yield a passing run,
even when the only material is `actual evidence`.

Done when requires each answer to carry the line it rests on. Recording
line_found=false while still passing the run does not enforce that
requirement, and turns an unsupported judge response into a successful
grade. Treat a pass without a supporting quotation from the supplied
material as unanswered, with a reason, so it fails a graded question and
leaves a reported question non-grading. Add a model-free test for each of
the two responses above; the current house test explicitly accepts a line
that is not in its material.

## Finding 3: External review checkout paths reveal the arm to the judge
Recommendation: fix now

In evals/agent-factory/harness/facts.py:115 and :140, a review found only
in another checkout gets `where: worktree:<absolute path>`. run.judged
serializes that fact into the judge prompt unchanged. run_one names the
work directory with the arm, setup and index at run.py:964-966.

I ran the vacuous-test fixture with the primary checkout on main and an
uncommitted review in repo-price-r4nd, under a work directory ending in
`-skill-house-0`. The facts and resulting judge prompt contained
`worktree:/tmp/next-vacuous-test-review-grade-...-skill-house-0/repo-price-r4nd`.
This is the external-checkout path the new review reader and its test
explicitly support. It defeats Done when's blinded judge requirement even
though the judge's own working directory is anonymous. Use an arm-free
checkout identifier in facts supplied to the judge and test the full prompt
with an external, uncommitted review under a normally named run directory.
